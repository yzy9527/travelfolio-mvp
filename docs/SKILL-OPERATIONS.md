# Skill pipeline operations

## Processes and permissions

NestJS API handles authenticated state changes, encrypts BYOK settings and serves artifacts as downloads. Independent Node Worker decrypts a user's key only while executing that user's claimed job. Worker artifacts live under WORK_ROOT/userUUID/jobUUID with mode 0700/0600 and cannot be served by Nginx. PostgreSQL is authoritative; local files are private recovery/inspection copies. Compose places API/Web/database on internal networks and gives only Worker its additional egress network. Docker's network isolation is defense in depth; safe-http still pins verified public DNS addresses, rejects private targets, redirects and unapproved ports, and limits response bytes.

The API holds the encryption key to save/rekey settings, so an operator or compromised API with database access can decrypt BYOK. This is not hardware-isolated key custody. Search key is Worker-only; API BRAVE_SEARCH_CONFIGURED is only a capability indicator.

## Upgrade

Back up PostgreSQL and KEY_ENCRYPTION_SECRET. Run the existing migrator; 002 is additive except expanding job status/index predicates. Legacy adopted content is untouched. Legacy queued work is marked LEGACY_JOB and must be recreated through outline review; it is never automatically approved. Do not roll back binaries while v2 jobs are active without draining the Worker and consulting the expanded schema.

## Recovery and billing

Each stage ends in a database checkpoint. A 1-second heartbeat extends a 60-second lease. Cancellation/disabled accounts abort active transports and fence candidate publication. A crash with no started external operation safely requeues the same stage. Any started or ambiguous paid operation becomes POSSIBLE_CHARGE; an operator cannot assume a rejected response was free. User resumes only after explicit acknowledgment. Successful results are cached by canonical input hash and stable operation key; retries use new upstream idempotency headers and retire ambiguous rows. Upstream provider idempotency support is not guaranteed.

Recovery does not delete current adopted versions. Inspect redacted error codes, stage and job events; do not log model request headers, settings or API keys. At most 5 explicit resumptions per job. Model output schema failure may still be billed. Fix its cause before resuming.

Outline prompts include a complete result-envelope example. Outline responses may also be direct objects containing all five required outline fields; they still pass the same strict outline schema, date and credential checks. Research packs also accept direct JSON matching the expected object or array shape, with the identical executable pack schema and retrieved-source binding; partial objects, unknown fields and invented references still fail. Invalid envelopes report only fixed diagnostics: envelope.missing_result, envelope.extra_fields, envelope.array or envelope.non_object. No response content or unknown field names are retained, and this compatibility handling performs no additional model call.

Research diagnostics retain the validator's issue code and typed array indices (for example research.places-core.sights.0.duration_minutes.invalid_type). Unknown path components are omitted while preserving the known pack/field prefix. Failed pages and snippets are excluded from model evidence; allowedSourceReferences explicitly lists retrieved source IDs and URLs. Insufficient source coverage must not be repaired by inventing records. For a locally authorized workflow test, use a separate demo job with explicit synthetic labels; never convert a live checkpoint to fixture data or claim fixture acceptance is live travel verification.

Model responses now distinguish completion envelope, truncation, filtering, refusal, empty content, invalid JSON, missing result envelope, outline schema, and research schema failures. The operation ledger stores only a bounded schema path and issue code (for example `outline.days.0.pace.invalid_enum_value`) with the safe error code and phase; it never stores the response body or credential. Response validation failures remain charge-ambiguous and are never retried automatically. An older `PROVIDER_INVALID_RESPONSE` row cannot be diagnosed more precisely because its response body was intentionally not retained. DeepSeek calls explicitly disable thinking mode for the JSON contract; output token bounds and strict server validation remain in force. Outline `changedPacks` is computed from the request by the server, not accepted from model output.

When no source page was retrieved, explicit resume retries failed page downloads using the completed search operations; it does not repeat successful paid searches. This also repairs older checkpoints that marked an all-failed evidence collection as complete. Once usable evidence has been checkpointed, it remains frozen for model retries. No database reset is needed. `RESEARCH_EVIDENCE_REQUIRED` means no usable page was retrieved; when every attempted page was rejected as an unsafe destination, the worker reports `UNSAFE_PROVIDER_HOST` instead. Other safe provider errors retain their specific code; ambiguous paid operations still take precedence as `POSSIBLE_CHARGE`. Job errors include only the service, safe phase/code and verified HTTP status. The operation ledger records those fields without credentials, request bodies, response bodies, URLs or queries. A DNS/pre-connect failure proved to occur before a paid request is `not_sent` and requires no billing acknowledgment; every request begun or otherwise uncertain remains ambiguous and requires acknowledgment before explicit recovery. No paid call is automatically retried.

## Worker DNS under a Fake IP proxy

`WORKER_DNS_MODE=cloudflare` (the Compose default) uses Cloudflare's JSON DoH at `cloudflare-dns.com` with its connection pinned to `1.1.1.1` or `1.0.0.1`. `WORKER_DNS_MODE=google` is the alternative, pinned to `8.8.8.8` or `8.8.4.4` at `dns.google`. Both use HTTPS certificate verification for the named DoH host. The Worker never resolves a DoH host through its system DNS or accepts an arbitrary resolver URL/IP. DNS A and AAAA answers and CNAME chains are checked before use; public-only address policy also runs immediately before every external connection. The selected public IP is fixed for that request while TLS still authenticates the original model, search, page, image or map hostname. Responses are cached for at most five minutes and at most 512 hostnames; failed answers are not cached. DoH failure stops the request with `PROVIDER_DNS_FAILED` and never silently falls back to system DNS.

The first pinned DoH address has a 1.2-second attempt limit, then the backup has up to three seconds. A/AAAA queries and all CNAME hops share one 4.5-second resolution deadline, below the safe HTTP layer's five-second DNS limit. Timed-out or cancelled DoH sockets are destroyed; an unresponsive primary therefore cannot consume the whole safe HTTP DNS allowance before the backup starts.

`WORKER_DNS_MODE=system` uses the OS resolver when it reliably returns real public addresses. It is unsuitable for a proxy that returns `198.18.0.0/15` Fake IPs. The Worker makes direct pinned-IP HTTPS connections and does not use `HTTP_PROXY`/`HTTPS_PROXY`; the host's transparent proxy/TUN routing must pass those connections. A successful DoH lookup alone does not prove that route works. Check DoH and a representative source/model/search HTTPS connection from inside the Worker container while the proxy is enabled. A site may still reject traffic or return an unsupported content type; such failures keep their specific safe code and HTTP status when a response was received. Do not turn off the public-IP check or TLS verification to address routing problems.

Proxy Fake IP DNS is incompatible with the public-address checks. The worker must receive real public addresses for model/search hosts, source websites, and their DNS aliases. Fixing only the model host does not repair arbitrary research pages. Check both A and AAAA results inside the worker: a single fake address, including an IPv4-mapped IPv6 address, rejects the destination. Do not disable the SSRF guard or allow the Fake IP subnet. Existing failed jobs show their previously stored error until explicitly resumed.

## Source and asset capability

Research search policy `destination-v4` explicitly supplies Brave `country` and `search_lang`. Mainland destinations use China (`CN`) and simplified Chinese; recognized overseas destinations use their search region and English tourist information, while Hong Kong/Taiwan use traditional Chinese. Unsupported Brave regions and multi-country itineraries use `ALL` with the destination still in the query. Destination hints are a bounded alias table, not a geocoder: unknown Chinese names default to China, unknown Latin names use global English, and ambiguous overseas destinations should include their country. Known cities receive province/country context; unknown locations do not get invented administrative details.

The research adapter calls Brave Web Search `POST /res/v1/web/search` with a JSON body and reads `web.results`. Brave's LLM Context `GET /res/v1/llm/context` instead takes query parameters and returns `grounding.generic` with extracted snippets; it is a distinct API and requires a separate parser and source/provenance policy before adoption. No LLM Context request is made by the current adapter.

Before fetching, the result title, snippet or URL hostname/path must mention the destination or a known alias. Country/province-only mentions cannot substitute for a recognized city. This conservative text filter can miss relevant pages and is not proof of geographic accuracy or official authority. No matching results raises `RESEARCH_NO_RELEVANT_SOURCES`; it never falls back to unrelated pages. Query spelling correction and search operators are disabled to preserve the supplied destination. Only destination data enters these searches, not departure, preferences or budget.

The new search policy uses a versioned operation key and hashes region/language with the query. Explicit recovery of an old job with unusable evidence performs a new, potentially billed search batch under this policy; subsequent retries reuse that batch. Already checkpointed usable evidence and completed packs remain frozen. The earlier English search rows are preserved, not overwritten or mistaken for the new requests.

BRAVE_SEARCH_API_KEY is mandatory for live pack research. Each pack has bounded fixed queries, controlled page retrieval and server-owned provenance. RESEARCH_OFFICIAL_HOSTS must be a reviewed exact host list; search ranking or model claims cannot declare a domain official. Without it, retrieved pages remain unclassified and official image acquisition remains pending. Image bytes alone do not prove subject, rights or visual quality. No map browser/screenshot capture is fabricated: missing maps are recorded as pending and visible in the artifact.

A browser-backed exact venue/image/map verification workflow is still a live acceptance requirement. This source port must not be advertised as complete destination handoff merely because fixtures, schema validation or a user checkbox passed.

## Retention and limits

Workspaces and operation results may contain private trip content and need the same backup/access controls as PostgreSQL. No automatic retention deletion is included. Schedule a documented operator retention policy separately. Bound disk usage and database growth at deployment. The API does not publish a work directory or accept arbitrary filenames.

## Verification before production

Run npm run check, then real PostgreSQL16 migration/locking tests and Docker Compose build. Configure a dedicated low-limit model/search test account. Generate a real non-template destination, approve its outline, inspect all eight modules/source identities/media, perform a scoped adjustment and confirm preserved evidence, cancel a running job, simulate worker restart, compare exported artifact hashes, and record actual desktop/mobile/offline interactions. Do not assert those live checks were run when only mocked transports were tested.

## Actual media and browser completion path

Worker `maps` now runs locally bundled MapLibre/OpenFreeMap capture when source-bound coordinates exist. Every external map byte is intercepted through the fixed host allowlist and pinned DNS transport; styles/tiles have SHA receipts and the screenshot binds full stop coordinates/source IDs. A secure Chromium launch/capture failure records pending/failed evidence, never a fake map. The worker image installs Chromium and CJK fonts; CHROMIUM_PATH is trusted absolute server configuration. Chromium sandbox stays enabled. Some container hosts require additional supported sandbox configuration; this application does not disable the sandbox automatically.

Worker `validate` renders once, executes real no-network desktop/mobile and exported-file interactions, records measured checks and screenshots, then attaches a separate certificate to the exact HTML SHA. Tested HTML bytes are not regenerated after acceptance. API iframe inherits the production CSP and permits only the immutable trusted runtime hash; the test suite catches hash drift.

Downloaded raster assets and map captures remain unreviewed until actual per-asset source/subject/watermark feedback. The candidate contact-sheet review creates a fresh compile-only version, optionally selects a reviewed image as cover, and reruns derived QA. It does not re-search or call a model. Existing candidate/adopted artifacts remain immutable. Missing media or unavailable browser means full handoff stays false; preview adoption requires explicit acknowledgment and keeps all warnings.

Provider contract note: each pack allows up to 24,000 output tokens and 400KB prompt bytes. A custom model must support JSON mode and these bounds; token/context limits and refusal/error behavior require real compatibility validation. No model autodetection, paid fallback or automatic paid repair is claimed. DeepSeek current Chat Completions schema was checked at https://api-docs.deepseek.com/api/create-chat-completion/ on 2026-09-30; model aliases can change, so confirm your selected model in the provider console.

Specific local destinations retain recognized city aliases for relevance. Shopping, food and practical modules search the recognized city context rather than restricting every query to a small attraction; sight and itinerary searches retain the exact requested destination. The v4 ledger namespace keeps prior paid results intact while allowing corrected failed-stage queries.

Research v4 returns up to ten results per search with twelve fetched pages per pack, and broadens two sight searches to recognized city context. Explicitly unconfirmed route distances may compile a preview with coordinate warnings; claimed measured routes still require source-bound coordinates. Missing maps, media and offline map QA remain pending and full handoff stays blocked.

Dining inventory may be smaller than the default targets only with explicit inventory_limit_reason and chain_limit_reason; these are rendered visibly and inventory shortage remains a QA warning. No branch, source or verification is synthesized to meet a count. Manual editorial corrections to the acceptance task are audited separately from original API checkpoint data and do not set successful QA claims.
